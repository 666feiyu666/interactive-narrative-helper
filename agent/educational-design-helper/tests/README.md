# Educational Design Helper automated verification

Run all component and repository contract checks with:

```powershell
npm run test:all
```

The suite verifies:

- complete v0.1 compatibility runs and strict v0.1/v0.2 schema isolation;
- formal-release hashes, counts, denominators, missingness, support IDs, and
  deterministic rebuild behavior;
- the 6 + Top-8 + Top-8 v0.2 candidate retrieval path, selected-reference
  traceability, tautological-pattern penalty, and typed run trace;
- provider-payload exclusion of source, path, excerpt, review, quality,
  confidence, limitation, public-title, URL, and retrieval-only fields;
- the v0.2 structured diagnosis, exactly three materially distinct directions,
  650–1800-character visible-content bounds, locally resolved references,
  internal-language exclusion, positive-effect-claim handling, and a maximum
  of one targeted repair;
- versioned Markdown and JSON export names plus local HTTP behavior; and
- six fixture scenarios: Journaling, middle-school cyberbullying, museum
  family visitors, a complete request, no direct precedent, and a Chinese
  query over English-language knowledge. The rejected first Journaling run is
  retained as a regression fixture.

Fixtures exercise deterministic software paths and validation boundaries; they
are not evaluations of semantic retrieval quality or design-advice quality.
Passing tests do not establish corpus coverage, knowledge validity, author
utility, or learning effectiveness.
