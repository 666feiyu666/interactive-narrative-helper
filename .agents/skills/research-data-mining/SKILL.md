# 研究型数据挖掘

## 明确任务边界

- 目标是形成可审查的研究证据，而不是单纯获得更多数据、填充下游知识库或交付一套应用。
- 区分用户确认的研究决定、直接观察、派生数据、解释、假设和未知项；不要把探索性发现写成预先确认的事实。
- 本 skill 同时负责研究方法和完成该方法所需的研究实现，可以直接创建与修改采集、清洗、筛选、编码、分析和审计脚本或 notebook，并运行可重跑的数据管线。
- 不因为研究工作包含代码就转交软件开发。只有用户明确决定把研究工具或结果产品化为完整前后端应用时，才使用 `guided-software-development`。
- 不提前规定下游机器学习、知识库或 Agent 契约。只有当前证据足以支持且用户确认后，才交给 `research-agent-building` 建立或检验 Agent 模型。
- 只有会改变研究问题、总体、构念、证据解释、伦理或权利边界的选择，才需要独立的研究决策记录。普通采集与清洗实现留在协议、工具、notebook、测试或 run report 中。

## 建立最小研究协议

在扩大采集或分析前，明确当前阶段真正需要的内容：

1. 研究问题、预期产出的知识主张，以及本轮不能回答的问题；
2. 核心术语、目标总体、观察单位、时间与来源覆盖范围；
3. 候选发现来源与目标总体的关系，避免把便利来源直接当成总体；
4. 纳入、排除和不确定状态及其理由；先用少量且有差异的样本试筛，修改规则时记录原因和影响；
5. 数据权利、隐私、伦理和外部服务约束。公开可访问不等于可以抓取、再发布或发送给外部模型。

协议可以随着探索更新，但必须保留修改原因，并区分修改前后的结果。版本或稳定标识用于证据定位，不表示研究必然朝一个已知产品目标成熟。不要在看到有利结果后静默改变标准。

## 实施研究数据工作

- 先检查项目已有数据、协议、字段、代码和人工编辑面，避免创建平行数据集、重复 review queue 或绕过 canonical source。
- 采用能够回答当前研究问题的最小实现。优先使用 notebook 做探索、解释和小样本核查；需要批量重跑或稳定转换时使用脚本。不要为了工程完整性建立不需要的服务、框架或接口。
- 保存来源清单、访问时间、标识符、权利状态和获取结果。保留会影响总体覆盖、证据解释或筛选审计的采集失败、拒绝与排除理由。
- 原始资料保持不可变或可恢复。受限、含个人信息或受版权保护的全文默认不进入 Git，只保存允许的 provenance、派生字段和最小证据摘录。
- 对去重、解析、清洗、过滤和派生字段记录规则、配置与输入输出标识，使转换可重跑。
- 在分析前定义字段语义、允许值、缺失表示和来源。涉及解释性编码时建立简短 codebook，并把代码或分类连接到原始证据位置。
- 先试标少量且有差异的样本，记录歧义、反例和规则修订。需要一致性时说明标注者、复核或裁决方式；不要让自动分类静默成为最终判断。
- 对研究脚本和 notebook 做与风险相称的验证，确认它们实现了已记录的转换；软件检查只能证明实现行为，不能证明研究总体、编码效度或结论成立。

## 判断证据能支持什么

- 检查覆盖、缺失、重复、来源偏差、解析错误、时间偏差和可获得性偏差，再解释频数或类型。
- 分开报告直接观察、计算结果和研究者解释；保持每项重要结论到来源或派生步骤的可追溯关系。
- 区分探索性模式、待验证假设和得到支持的结果。保留不符合预期的数据、负例和不确定项。
- 不从相关性声称因果，不把来源样本外推为未覆盖总体，不用流畅摘要替代编码或证据。
- 将结论标为 `supported`、`suggestive`、`contested` 或 `currently_unsupported`，并说明适用范围、限制和替代解释。

## 交给 Agent 建模

只有当一项数据发现的来源、含义、适用范围和成熟状态已明确，并且用户确认要探索其 Agent 用途时，才交给 `research-agent-building`。交接应说明：

- 得到支持或仍属探索性的发现；
- 可用证据和不可传递的受限材料；
- 允许的概括范围；
- 缺失、不确定项和反例；
- Agent 不得静默填补的知识空缺。

Agent 原型暴露新的证据缺口时，返回本 skill 补充筛选、编码或分析；不要用 prompt、schema 或生成内容替代缺失的研究证据。

## 保持产物简洁

只创建当前研究真正需要的最小产物，通常从以下内容中选择：研究协议与决策记录、来源清单、筛选记录、字段表或 codebook、研究 notebook、可重跑脚本、派生数据、转换日志、分析结果和限制说明。不要为了流程完整而创建空模板、重复文档或尚无证据支持的下游架构。

## 完成检查

确认研究问题、总体和观察单位明确；每项纳入、排除和转换可追溯；权利与隐私边界已记录；分析可由保存的输入、规则和配置重跑；重要结论能回到证据；偏差、未知项和不可支持的结论没有被隐藏；任何 Agent 建模输入都保留了其证据成熟度和限制。
